# Card

A composable content container for news, events, people, resources, videos, and statistics, with an item-wide primary title link when present.

## When to use

- Present related content as tiles inside a `Column`.
- Combine images, titles, excerpts, and metadata for a single destination.
- Show contact details alongside a person's profile link.
- Use a video figure or statistics without requiring a navigation link.

## Import

```tsx
import { Card } from '@cuweb/raven-design-system';
```

## Basic usage

```tsx
<Card>
    <Card.Header title="Profile details" link="/people/profile" />
    <Card.Body>
        <Card.PeopleMeta jobTitle="Staff member">
            <a href="mailto:person@example.test">Email person</a>
        </Card.PeopleMeta>
    </Card.Body>
</Card>
```

One linked `Card.Header` automatically makes the image, static content, and padding clickable using the existing title anchor. Email, phone links, buttons, and video controls remain independent. Plain phone text is not automatically converted to a link.

Use one primary header per item. Sibling multiple headers retain local links; competing primary headers in separate nested containers are unsupported. Custom wrappers must not introduce positioning, clipping, or stacking contexts between the title anchor and the card root. `LinkProvider` implementations must render an anchor and forward its attributes.

Static CMS markup with `.cu-card`, `.cu-card__header`, and `.cu-card__header-title > a[href]` receives the same CSS behavior without a click script. A card without a linked title, including video-only cards and loaders, gets no enlarged navigation target. The overlay can make selecting static text less convenient.

`noHover` retains its existing Card modifier class; it does not disable links. This differs from Listing's existing pointer-disabling modifier.

## Accessibility

- The root is a noninteractive `div`; a linked title remains a native anchor with its existing title as its accessible name. No duplicate link or extra tab stop is added.
- The primary link has an inset full-card focus indicator. Secondary links and controls keep their own focus indicators and keyboard actions.
- Title links use `LinkProvider`, preserving native link semantics and client-side routing.
- Choose `as="h2"` or `as="h3"` on `Card.Header` to match the page heading hierarchy.
- Supply meaningful image alt text; use empty alt text for decorative images.
- Date/time thumbs are decorative. Include equivalent information in accessible metadata.
- Video play links have an accessible name; the iframe has a title.
- Scroll reveal respects reduced-motion preferences.
